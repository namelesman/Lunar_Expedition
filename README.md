# Lunar Landing Site Navigator

NASA Space Apps Challenge 2026 — challenge
[*Lunar Landing Site Navigator*](https://www.spaceappschallenge.org/2026/challenges/lunar-landing-site-navigator/).
Team from Recife, Brazil.

A web app to compare lunar landing sites and dates in seconds: where the **Sun** and the **Earth**
are relative to the **real terrain horizon** at each site, how long until sunset / Earthset, and the
power and direct-to-Earth communication windows over the coming weeks — on a real-time 3D Moon built
from NASA LRO data.

> Work in progress (hackathon, 14–15 Nov 2026). See [`docs/challenge.md`](docs/challenge.md) for the
> official objectives and how each one maps to the app.

## Repository layout

```
apps/web/        Next.js (App Router) + TypeScript — UI, 3D globe, /api routes
packages/core/   Pure, tested logic: shared types, lat/lon → 3D, Sun/Earth geometry, horizon, A*
scripts/         Node + TypeScript data pipeline (GLB optimization, horizon masks, terrain grids, fixtures)
data/            sites.json (curated landing sites with official sources)
docs/            Challenge summary and design notes
```

Raw NASA files (TIFF/EXR/GLB) and generated tiles are **never committed**; the scripts in
`scripts/` download and regenerate everything.

## Quick start

```bash
npm install
npm run dev        # http://localhost:3000
npm test           # unit tests (packages/core)
npm run check      # typecheck + tests + production build
```

### Data pipeline (Node + TypeScript, `scripts/`)

Everything runs on Node 22+ with `tsx`; no Python. Raw NASA files go in `data/raw/` (git-ignored).

```bash
npm run glb:optimize -- path/to/Moon_NASA_LRO_8k_Topo.glb apps/web/public/models   # SVS #14959 → web GLBs
npm run glb:fit -w @lunar/scripts      # calibrate the GLB against LOLA (needs data/raw/svs-4720/ldem_16_uint.tif)
npm run data:horizons                  # horizon masks per site (needs ldem_64_uint.tif)
npm run data:dem-tiles                 # LOLA DEM tiles for browser horizons (--download fetches the rasters)
npm run data:fixtures                  # albedo fixture for the core tests
npm run sky:textures                   # star map (SVS #4851 starmap_2020_8k.exr) + Earth (Blue Marble NG)
npm run assets:stage                   # stage models + sky for the static assets project
```

Heavy web assets (optimized GLBs, star map, DEM tiles) are git-ignored and served from a separate
static Vercel project (`NEXT_PUBLIC_ASSETS_BASE_URL`); `npm run assets:stage` then
`vercel deploy --prod` in `data/cache/assets-site` publishes them. The GLBs and the star map are
uploaded (~15 MB). The DEM tiles (~0.6 GB, 8,800 files) are generated by that project's build: it
downloads the NASA rasters, checks their SHA-256 and runs the bundled `dem-tiles` script. A Vercel
Hobby CLI upload is capped at 100 MB, but files a build creates are not.

### Terrain horizon for custom points (computed in your browser)

Curated sites use precomputed masks (`apps/web/public/data/horizons.json`). For any other point
(typed coordinates or a double-click on the Moon) a Web Worker downloads only the LOLA tiles that
point needs and runs the **same** `horizonMask` (`packages/core/src/terrain.ts`): 720 azimuths,
terrain marched to 300 km with exact curvature, observer 2 m above the ground. There is no server
code. If a tile fails or nothing comes back within 15 s, the point keeps a smooth-sphere horizon
and the panel says so.

| Band | Layer (finest first) | Source | Resolution |
| --- | --- | --- | --- |
| ≤ 50 km | `polar-s-80m` (≤ 80°S) | LOLA GDR LDEM_80S_80M | 80 m |
|  | `ldem-64-n` (≥ 85°N) | ldem_64 resampled to a polar grid | 118 m |
|  | `ldem-64` | CGI Moon Kit ldem_64, 5° tiles | 64 px/° (≈474 m) |
| 50–300 km | `polar-s-960m` (≤ 75°S) | LDEM_75S_120M, 8×8 mean | 960 m |
|  | `ldem-16-s` / `ldem-16-n` (|lat| ≥ 60°) | ldem_16 resampled to polar grids | 948 m |
|  | `ldem-16` | CGI Moon Kit ldem_16, 30° tiles | 16 px/° (≈1.9 km) |

Near the poles, equirectangular tiles are mostly redundant columns, and a 300 km radius spans
every longitude. The polar grids keep every site within budget: ≤ 4.1 MB per site over all
probes, including both poles.

Validation (`packages/core/test/demTiles.test.ts`, run after `npm run data:dem-tiles`):

- Tiles are lossless. Through the tile path, ldem_64 reproduces `horizons.json` exactly
  (Apollo 11, IM-1, IM-2, Shackleton). Every layer is also re-read from its tiles and must be
  bit-identical to the full raster.
- The coarser 50–300 km layers change the horizon by at most 0.046° (IM-1; RMS 0.003°). They do not
  change it at Apollo 11, IM-2 or Shackleton.
- South of 80°S the app uses the 80 m LOLA DEM for the first 50 km. It resolves relief that ldem_64
  smooths, so it differs from `horizons.json` by up to 2.7° (IM-1), 1.6° (IM-2) and 0.7°
  (Shackleton). Those differences are real terrain, not an error.

Measured in the browser (Chromium, cold cache, tiles from the production assets host over HTTPS,
16 parallel requests):

| Point | Downloaded | Tiles | Time to horizon | of which the march |
| --- | --- | --- | --- | --- |
| Equatorial 8.5°N 31.4°E | 2.0 MB | 7 | 1.1 s | 0.3 s |
| South polar 89.45°S 137.31°W | 3.3 MB | 126 | 2.7 s | 0.4 s |
| North polar 86.2°N 40°W | 3.7 MB | 89 | 2.1 s | 0.4 s |

Tiles stay in the worker's memory, so a nearby second point downloads little or nothing.

## Data and credits

- NASA's Scientific Visualization Studio — CGI Moon Kit and the LRO 8k topographic Moon model.
- Lunar Reconnaissance Orbiter Camera (LROC), NASA / GSFC / Arizona State University.
- Lunar Orbiter Laser Altimeter (LOLA), NASA / GSFC — CGI Moon Kit ldem_16/ldem_64 and the LOLA GDR
  south polar DEMs LDEM_80S_80M and LDEM_75S_120M (imbrium.mit.edu, PDS Geosciences Node).
- NASA SVS Deep Star Maps 2020 (svs.gsfc.nasa.gov/4851) — background sky, oriented for the selected date.
- NASA Earth Observatory Blue Marble Next Generation (Reto Stöckli) — Earth texture.

The Sun and the Earth in the 3D view are drawn at their true directions and apparent sizes
(≈0.53° and ≈1.9° from the Moon), with an optional 4× "not to scale" mode; the Earth shows its real
phase and the face turned toward the Moon at that instant.
